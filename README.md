# simd-depth-parser

Парсер событий стакана Binance Futures (`depthUpdate`, JSONL) на AVX2.
Разбирает событие в структуру с ценами и объёмами в fixed-point `int64`
(×10⁸), без `double` и без аллокаций на горячем пути.

Написан для конкурса HFT-фонда Fast Forward по парсингу рыночных данных
(май 2026). Метрика конкурса — p95 латентности разбора одного события.

## Результаты

Публичный датасет конкурса — 1 162 781 реальное событие, 3 прогона.
Замер в харнессе организаторов против их эталонного парсера, AMD Ryzen 7 5700U,
ядро закреплено:

| парсер     |    p50 |     p95 |     p99 |
|------------|-------:|--------:|--------:|
| эталонный  | 561 нс | 1693 нс | 4298 нс |
| этот       | 140 нс |  561 нс | 1212 нс |
| ускорение  |  4,0×  |   3,0×  |   3,5×  |

Датасет и харнесс организаторов в репозиторий не входят. Для воспроизведения
есть свой бенчмарк на синтетических данных (см. ниже); его эталонный парсер
другой, поэтому абсолютные цифры отличаются.

## Как устроено

Ключи верхнего уровня (`T`, `s`, `u`, `pu`, `b`, `a`) разбираются скалярно:
ключ определяется по первому символу, лишние поля пропускаются. Почти всё
время уходит на массивы уровней `[["3129.60","698.140"], ...]`, и они
разбираются векторно, по одному уровню за итерацию:

1. **Поиск разметки.** Загружаются 64 байта начиная с цены. `cmpeq` +
   `movemask` дают 64-битные маски кавычек и точек. Позиции трёх кавычек
   (конец цены, начало и конец объёма) — `countr_zero` со сбросом младшего
   бита, позиции точек — маски внутри каждого числа. Без ветвлений.
2. **Выравнивание цифр.** Цена и объём кладутся в две половины 256-битного
   регистра. `pshufb` по предвычисленной таблице `[длина][позиция точки]`
   выкидывает точку и прижимает цифры к правому краю 16-байтной полосы,
   свободные позиции обнуляются.
3. **Свёртка в число.** После вычитания `'0'` пары цифр сворачиваются
   `maddubs` (×10, ×1), четвёрки — `madd` (×100, ×1): в каждой полосе
   получается четыре 4-значных блока. Из них собираются старшие и младшие
   8 цифр, а масштаб до 10⁸ берётся из таблицы степеней по числу знаков
   после точки. Число без точки — частный случай той же таблицы.
4. **Запись.** Уровни копятся в буфере на стеке и вставляются в `vector`
   одним `insert`, без проверки ёмкости на каждый элемент.

Если число длиннее 16 символов или уровень не помещается в 64-байтное окно,
он разбирается скалярным путём.

## Сборка и запуск

Нужны x86-64 с AVX2, GCC 13+ или Clang 17+, CMake 3.20+.

```sh
cmake -B build && cmake --build build -j
python3 tools/gen.py 200000 > events.jsonl   # синтетические события
./build/depth_bench events.jsonl 3 2         # файл, прогонов, ядро
```

`depth_bench` сначала сверяет результат с простым скалярным
`ReferenceParser` на каждом событии, затем меряет латентность обоих
через `rdtsc`. Генератор с вероятностью 1% вставляет числа длиннее
16 символов, чтобы проверять и скалярный путь. CI запускает эту
проверку на каждый push.

## Использование

Парсер — один заголовочный файл:

```cpp
#include "depth_parser/simd_parser.hpp"

depth_parser::SimdDepthParser parser;
depth_parser::DepthEvent event;
event.bids.reserve(4096);
event.asks.reserve(4096);
parser.ParseTo(line, event);
```

## Ограничения

Это конкурсный парсер под конкретный формат, а не валидирующий JSON-парсер:

- после конца строки должно быть не меньше **64 байт читаемой памяти**;
- вход считается корректным: без пробелов, с ключами в формате Binance,
  ошибки не проверяются;
- `bids`/`asks` должны быть пустыми на входе, с заранее
  зарезервированной ёмкостью.

## История

Первый коммит — версия, отправленная на конкурс. Во втором исправлен баг,
который бенчмарк нашёл на синтетических данных: после скалярного fallback
терялись следующие уровни (в датасете конкурса длинных чисел не было), и
убран вызов `__builtin_ctzll(0)`. На скорость на датасете конкурса это
не повлияло.
